# 테스트 개발 안내

테스트는 실제 후잉 계정이나 앱 자격 증명 없이 실행합니다.

## 실행

```bash
make test              # 빠른 단위 테스트
make check             # 단위 테스트와 go vet
make test-race         # race detector와 무작위 실행 순서
make test-integration  # CLI 도움말, 거래 요청과 오류 처리 검사
make test-cover        # coverage.out 생성과 함수별 커버리지
go tool cover -html=coverage.out
```

PR과 `main` 브랜치 push에서는 Go 1.22와 최신 안정 버전으로 vet, race 검사, 커버리지 측정, CLI 통합 테스트를 실행합니다. 작업 브랜치 push는 별도로 검증하지 않아 PR과의 중복 실행을 피합니다. 같은 PR이나 `main`에 새 커밋이 올라오면 이전에 진행 중이던 검증을 취소합니다. 태그 릴리스와는 별개 워크플로입니다.

## TDD 순서

1. 변경할 동작을 같은 이름의 `*_test.go`에 테스트로 작성합니다. 정상 입력뿐 아니라 중요한 오류나 경계 조건을 포함합니다.
2. 해당 테스트만 실행해 의도한 이유로 실패하는지 확인합니다. 컴파일 오류나 잘못된 테스트 준비로 인한 실패는 동작 검증이 아닙니다.
3. 테스트를 통과시키는 데 필요한 구현을 수정합니다.
4. 테스트를 유지한 채 코드를 정리하고 `make check`, `make test-race`를 실행합니다. CLI 디스패치나 도움말을 바꿨다면 `make test-integration`도 실행합니다.

예를 들어 일괄 입력의 API 오류 처리만 검증하려면 다음 명령을 사용합니다. `-count=1`은 캐시된 성공 결과를 재사용하지 않도록 합니다.

```bash
go test ./api -run '^TestCreateEntriesBatchStopsOnError$' -count=1
```

## 테스트 격리

- HTTP는 클라이언트별 가짜 `http.RoundTripper`로 대체합니다. 실제 후잉 URL로 접속하지 않습니다. TUI 단위 테스트는 해당 화면이 사용하는 API 인터페이스에 가짜 클라이언트를 주입합니다.
- 설정 저장과 인증 완료 테스트는 `t.TempDir()`를 홈 디렉터리로 사용합니다. 환경변수는 `t.Setenv`로 설정하고 자동 복원합니다.
- 환경변수나 전역 상태를 바꾸는 테스트는 병렬로 실행하지 않습니다. 나머지는 독립성을 확인한 뒤 `t.Parallel()`을 사용합니다.
- 재시도 대기는 클라이언트의 내부 대기 함수로 교체해 횟수와 간격을 검증합니다. 캐시 만료는 음수 TTL로 확인하고, 날짜 경계는 고정 시각을 전달해 검증합니다.
- CLI 통합 테스트에는 `integration` 빌드 태그를 붙입니다. 임시 홈과 작업 디렉터리에서 실행하고 후잉 관련 환경변수를 제거합니다. `os.Exit`을 사용하는 거래 핸들러는 별도 테스트 프로세스에서 실행하며, 그 자식 프로세스 안에서만 `http.DefaultTransport`를 교체해 요청을 기록하고 가짜 응답을 반환합니다.

## 현재 보호하는 동작

HTTP 요청의 인증 헤더와 쿼리, 폼 인코딩, HTTP 오류 분류, 재시도 한도, 거래 일괄 입력의 분할과 실패 중단을 검증합니다. OAuth 토큰 요청과 교환, 인증 저장과 임시 토큰 정리, 설정 파일 권한과 저장 복원도 포함합니다.

거래 CLI는 추가, 반복과 할부, JSON 파일 일괄 입력, 단건과 복수 수정, 삭제의 요청 내용과 실패 시 종료 코드, stdout과 stderr를 검사합니다. 빈 메모 지우기, 섹션 지정, 검색 필터와 커서 전달, 항목 종류 추론도 검증합니다.

TUI는 초기 화면 결정과 메뉴 이동 외에 거래 입력의 성공, 실패, 취소, 변경 없는 수정, 날짜와 금액 검증을 검사합니다. 저장과 삭제 중 중복 동작 방지, 삭제 후 재조회, 더보기 커서와 마지막 페이지 처리도 포함합니다.

기존 파싱과 키 입력 테스트도 함께 실행합니다. 커버리지 숫자는 누락 경로를 찾는 데 사용합니다. 항목 관리, 카드, 예산 등 다른 기능의 쓰기 명령과 화면 저장 흐름은 아직 검증을 더 보강해야 합니다. 현재 테스트는 가짜 응답에 대한 계약을 보호하며 실제 후잉 서버와의 호환성까지 보장하지는 않습니다.
